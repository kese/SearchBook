# SearchBook

한국교통대학교 도서관의 EM/WM 등록번호를 일괄 조회해 Excel로 정리하는 Windows GUI 프로그램입니다.

## 왜 C#/.NET WPF인가

- Python과 패키지를 별도로 설치할 필요 없이 Windows 실행 파일로 배포할 수 있습니다.
- 파일 드래그앤드롭, 취소, 진행률, 고해상도 화면을 Windows 네이티브 UI로 처리합니다.
- 외부 Excel 라이브러리 없이 `.xlsx`를 직접 읽고 써 의존성을 줄였습니다.

## 주요 기능

- `.xlsx`, `.txt`, `.csv`, `.tsv` 파일 드래그앤드롭
- 파일 전체에서 EM/WM 등록번호 자동 추출 및 중복 제거
- 등록번호별 도서상태, 반납기한, 소장위치, 청구기호, 서명, 저자, 출판사, 출판년, ISBN, 상세 URL 수집
- 도서관 결과의 빈 항목은 `docs`의 전체 도서목록에서 보완하고, 원격 조회가 미확인/실패이면 로컬 전체정보를 사용
- 서버 오류 재시도, 요청 간격 설정, 진행률과 남은 시간 표시
- 50건마다 자동저장, 사용자 중지 시 처리 결과 보존
- 필터와 고정 헤더가 포함된 Excel 결과 생성
- 고양이 앱 아이콘과 알림 영역(트레이) 아이콘, 트레이 메뉴(열기/종료)
- 트레이 `업데이트 확인`: GitHub 최신 릴리즈 비교, self-contained ZIP 우선 다운로드, 크기와 SHA-256 검증

## 실행

일반 PC에는 `dist\SearchBook-self-contained-win-x64.zip`을 사용합니다. ZIP을 완전히 압축 해제한 뒤 `SearchBook.exe`를 더블클릭하면 별도의 .NET 설치 없이 실행됩니다.

`dist\SearchBook`과 `SearchBook-win-x64.zip`은 용량이 작은 프레임워크 의존형 배포본이며, 대상 PC에 .NET 10 Desktop Runtime x64가 필요합니다.

1. EM/WM 등록번호가 들어 있는 파일을 창으로 끌어 놓습니다.
2. 처음에는 작은 목록으로 시험합니다.
3. `조회 시작`을 누릅니다.
4. 완료 결과는 실행 파일 옆 `results` 폴더에 자동 저장됩니다.

실행 파일 옆 `docs` 폴더에는 번호대별 전체 도서목록이 포함됩니다. 원격 조회에 성공하면 현재 도서상태와 반납기한을 우선하고, 비어 있는 서명·저자·출판정보 등을 로컬 목록으로 보완합니다. 원격 조회가 실패하더라도 로컬에 정확한 등록번호가 있으면 `제적`, `소재불명`, `파손자료` 등을 포함한 상태와 전체 서지정보를 결과에 기록합니다. 로컬 목록에도 정확히 일치하는 EM/WM 번호가 없을 때만 `미확인`으로 남습니다.

현재 포함된 `18-26.xls` 기반 로컬 스냅샷은 2026-08-06 기준 EM 69,685건입니다. 이 원본에는 WM 행이 없으므로 EM의 숫자 부분이 같다는 이유로 WM 정보에 재사용하지 않습니다. WM은 도서관 실시간 조회 또는 향후 추가되는 정확한 WM 로컬 행으로만 확인합니다.

명령줄에서 입력 파일을 함께 넘겨도 즉시 불러옵니다.

```powershell
.\SearchBook.exe "C:\path\등록번호.xlsx"
```

## 업데이트 확인

트레이 아이콘을 우클릭하고 `업데이트 확인`을 누르면 현재 실행 버전과 GitHub 최신 릴리즈 태그를 비교합니다. 새 버전이 있으면 `SearchBook-self-contained-win-x64.zip`을 우선 선택하고, 없으면 `SearchBook-win-x64.zip`을 사용합니다. 다운로드 파일은 실행 파일 옆 `updates\<버전>` 폴더에 저장되며 GitHub가 제공하는 SHA-256이 있으면 반드시 검증합니다. 실행 중인 프로그램을 자동으로 덮어쓰지는 않습니다.

공개 저장소는 추가 설정 없이 동작합니다. 현재처럼 private 저장소라면 릴리즈 읽기 권한이 있는 토큰을 실행 파일 옆 `.env` 또는 앱을 실행한 프로젝트 폴더의 `.env`에 설정할 수 있습니다. 트레이에서 `업데이트 확인`을 누를 때마다 파일을 다시 읽으며, 프로세스 환경변수가 설정돼 있으면 그 값을 우선합니다. `.env`는 Git과 Release ZIP에서 제외됩니다.

```dotenv
SEARCHBOOK_GITHUB_TOKEN=여기에_토큰_입력
```

프로젝트 로컬 빌드는 루트의 `.env`를 자동으로 찾으므로 `SearchBook.exe`를 직접 실행해도 됩니다. 배포본을 다른 위치에 풀었다면 `SearchBook.exe`와 같은 폴더에 `.env`를 두세요.

환경변수 방식도 계속 지원합니다.

```powershell
$env:SEARCHBOOK_GITHUB_TOKEN = (gh auth token)
.\SearchBook.exe
```

토큰이 없거나 권한이 부족하면 자동 다운로드 대신 로그인된 브라우저에서 GitHub 릴리즈 페이지를 열 수 있습니다. 토큰 파일은 평문이므로 공유하거나 Release ZIP에 넣지 마세요.

## 입력 형식

등록번호가 어느 열에 있든 `EM` 또는 `WM`으로 시작하는 값을 찾습니다. 대소문자는 구분하지 않으며 중복은 첫 항목만 남깁니다.

## 빌드와 테스트

모든 SDK, 캐시, 임시 파일은 프로젝트 폴더 안에 둡니다.

```powershell
.\build-release.ps1
.\build-release.ps1 -SelfContained
```

테스트는 저장된 실제 응답 파싱, TXT 입력, XLSX 왕복, EM/WM 번호대 계산, 로컬 전체정보 적용, 원격/로컬 병합 우선순위, 실제 제적·소재불명 도서, GitHub 업데이트 판정·다운로드·SHA-256 검증을 검사합니다. `--live`를 붙이면 공개 등록번호 한 건을 현재 서버에서 실제 조회하고, `--github-live`는 토큰이 있는 환경에서 private GitHub 릴리즈 다운로드를 검증합니다.

```powershell
.\.tools\dotnet\dotnet.exe run --project .\Tests\SearchBook.Tests.csproj -c Release --no-restore
```

## 주의

- 도서관 서버의 HTML 구조가 바뀌면 파서를 조정해야 할 수 있습니다.
- `docs`의 기준 Excel을 교체할 때는 `등록번호`와 `도서상태` 헤더를 반드시 유지하고, 전체정보 보완을 위해 `소장위치`, `청구기호`, `서명`, `저자`, `출판사`, `출판년`, `ISBN`, `최종변경일`, `기준일` 열도 유지하는 것이 좋습니다. 파일명은 `180k.xlsx`처럼 1만 번호 구간에 맞춥니다.
- 1만 건은 검색과 소장정보 요청이 각각 필요해 수 시간이 걸릴 수 있습니다.
- 기본 0.7초 간격을 권장합니다. 서버가 느리거나 오류가 증가하면 1.0~1.5초로 늘리세요.
- 로그인이나 개인정보는 사용하지 않습니다.
