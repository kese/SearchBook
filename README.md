# SearchBook

한국교통대학교 도서관의 EM/WM 등록번호를 일괄 조회해 Excel로 정리하는 Windows GUI 프로그램입니다.

## 왜 C#/.NET WPF인가

- Python과 패키지를 별도로 설치할 필요 없이 Windows 실행 파일로 배포할 수 있습니다.
- 파일 드래그앤드롭, 취소, 진행률, 고해상도 화면을 Windows 네이티브 UI로 처리합니다.
- 외부 Excel 라이브러리 없이 `.xlsx`를 직접 읽고 써 의존성을 줄였습니다.

## 주요 기능

- `.xlsx`, `.txt`, `.csv`, `.tsv` 파일 드래그앤드롭
- 파일 전체에서 EM/WM 등록번호 자동 추출 및 중복 제거
- 클립보드 등록번호 붙여넣기와 입력 값/중복 제거 요약
- 등록번호별 도서상태, 반납기한, 소장위치, 청구기호, 서명, 저자, 출판사, 출판년, ISBN, 상세 URL 수집
- 도서관 결과의 빈 항목은 `docs`의 전체 도서목록에서 보완하고, 조회결과는 `대기`, `조회중`, `성공`, `실패`로 구분
- 웹 소장위치는 `중앙도서관 / 보존서고`처럼 도서관 지점과 자료실을 함께 표시
- 서버 오류 재시도, 요청 간격 설정, 진행률과 남은 시간 표시
- 50건마다 자동저장, 사용자 중지 시 처리 결과 보존, 기존 결과 Excel에서 미완료 작업 재개
- 결과 검색, 네 가지 상태 필터, 실패 행만 선택 재조회
- WM 기준 Excel(`wm00010000-300000.xls`)과 실시간 조회 결과의 일치·불일치 비교 및 필터
- 필터와 고정 헤더가 포함된 Excel 결과 생성, 작업 중 안전한 미리보기
- 사용자 데이터 폴더 열기, 개인정보를 제외한 진단 정보 저장
- 고양이 앱 아이콘과 알림 영역(트레이) 아이콘, 트레이 메뉴(열기/종료)
- 앱과 트레이의 `업데이트 확인`: GitHub 최신 릴리즈 비교, self-contained ZIP 우선 다운로드, 크기와 SHA-256 검증

## 실행

일반 PC에는 `dist\SearchBook-self-contained-win-x64.zip`을 사용합니다. ZIP을 완전히 압축 해제한 뒤 `SearchBook.exe`를 더블클릭하면 별도의 .NET 설치 없이 실행됩니다.

`dist\SearchBook`과 `SearchBook-win-x64.zip`은 용량이 작은 프레임워크 의존형 배포본이며, 대상 PC에 .NET 10 Desktop Runtime x64가 필요합니다.

1. EM/WM 등록번호가 들어 있는 파일을 창으로 끌어 놓습니다.
2. 처음에는 작은 목록으로 시험합니다.
3. `조회 시작`을 누릅니다.
4. 완료 결과는 `%LocalAppData%\SearchBook\results`에 자동 저장됩니다. 앱의 `도구 > 결과 폴더 열기`로 바로 이동할 수 있습니다.

중단된 작업은 상단의 `작업 재개`에서 SearchBook 결과 Excel을 선택하면 미완료 행만 이어서 조회합니다.

실행 파일 옆 `docs` 폴더에는 번호대별 전체 도서목록이 포함됩니다. 원격 조회에 성공하면 현재 도서상태와 반납기한을 우선하고, 비어 있는 서명·저자·출판정보 등을 로컬 목록으로 보완합니다. 원격 조회가 실패하더라도 로컬에 정확한 등록번호가 있으면 `제적`, `소재불명`, `파손자료` 등을 포함한 상태와 전체 서지정보를 결과에 기록합니다. 원격과 로컬에서 모두 찾지 못한 행은 `실패`가 됩니다. 실제 데이터 출처는 별도 `정보출처` 열에서 `도서관 실시간 조회`와 `로컬 전체목록`으로 구분합니다.

현재 포함된 `18-26.xls` 기반 로컬 스냅샷은 2026-08-06 기준 EM 69,685건입니다. 이 원본에는 WM 행이 없으므로 EM의 숫자 부분이 같다는 이유로 WM 정보에 재사용하지 않습니다. WM은 도서관 실시간 조회 또는 향후 추가되는 정확한 WM 로컬 행으로만 확인합니다.

`wm00010000-300000.xls`는 WM 기준 Excel로 함께 사용합니다. 배포본은 Excel 설치에 의존하지 않도록 이 원본에서 변환한 `docs\wm00010000-300000.xlsx`를 자동으로 읽습니다. 실시간 조회가 성공하면 도서상태·소장위치·청구기호·서명과 양쪽에 값이 있는 서지 항목을 기준 행과 비교합니다. 화면에서는 `조회결과`와 `도서상태`를 색상으로 구분하고, 조회결과 셀에 마우스를 올리면 기준 비교 세부사항을 확인할 수 있으며, WM 기준 요약과 `WM 일치`·`WM 불일치` 필터도 제공합니다. 저장 Excel에는 `기준 Excel 비교`와 `기준 비교 세부사항`을 별도 열로 남깁니다. 실시간 조회가 실패하면 `실시간 미확인`, 기준 행이 없으면 `기준 없음`으로 구분합니다. 현재 원본의 유효 WM 행은 19,372건이며 실제 등록번호 범위는 `WM00010000`~`WM00030000`입니다. 파일명에 포함된 300000까지의 행이 모두 존재한다고 추정하지 않습니다.

명령줄에서 입력 파일을 함께 넘겨도 즉시 불러옵니다.

```powershell
.\SearchBook.exe "C:\path\등록번호.xlsx"
```

## 입력 형식

등록번호가 어느 열에 있든 `EM` 또는 `WM`으로 시작하는 값을 찾습니다. 대소문자는 구분하지 않으며 중복은 첫 항목만 남깁니다.

## 빌드와 테스트

모든 SDK, 캐시, 임시 파일은 프로젝트 폴더 안에 둡니다.

```powershell
.\build-release.ps1
.\build-release.ps1 -SelfContained
```

테스트는 저장된 실제 응답 파싱, TXT 입력, XLSX 왕복, EM/WM 번호대 계산, 로컬 전체정보 적용, WM 기준 Excel 일치·불일치 판정, 원격/로컬 병합 우선순위, 실제 제적·소재불명 도서, GitHub 업데이트 판정·다운로드·SHA-256 검증을 검사합니다. `--live`를 붙이면 공개 등록번호 한 건을 현재 서버에서 실제 조회하고, `--github-live`는 토큰이 있는 환경에서 private GitHub 릴리즈 다운로드를 검증합니다.

```powershell
.\.tools\dotnet\dotnet.exe run --project .\Tests\SearchBook.Tests.csproj -c Release --no-restore
```

## 주의

- 도서관 서버의 HTML 구조가 바뀌면 파서를 조정해야 할 수 있습니다.
- `docs`의 기준 Excel을 교체할 때는 `등록번호`와 `도서상태` 헤더를 반드시 유지하고, 전체정보 보완을 위해 `소장위치`, `청구기호`, `서명`, `저자`, `출판사`, `출판년`, `ISBN`, `최종변경일`, `기준일` 열도 유지하는 것이 좋습니다. WM 원본처럼 `자료명`, `자료상태`, `소장분관`, `소장서고`를 사용하는 파일도 지원합니다. 파일명은 `180k.xlsx`처럼 1만 번호 구간에 맞추며, WM 비교 기준 파일은 `wm00010000-300000.xlsx` 이름을 사용합니다.
- 1만 건은 검색과 소장정보 요청이 각각 필요해 수 시간이 걸릴 수 있습니다.
- 기본 0.7초 간격을 권장합니다. 서버가 느리거나 오류가 증가하면 1.0~1.5초로 늘리세요.
- 로그인이나 개인정보는 사용하지 않습니다.
